🔧 Checklist Implantação e Documentações Utilizadas

Guia completo com os passos necessários para garantir uma implantação bem-sucedida do sistema.

1. Verificação da Autorização de Implantação e Autorização de Cobrança

Autorização de Implantação

  • Antes de iniciar a implantação, é obrigatória a verificação da existência da autorização de implantação no chamado correspondente.
  • Caso não esteja anexada, o Gerente de Projeto deve ser imediatamente comunicado.
  • O Gerente será responsável por solicitar ao time comercial a inclusão do documento no chamado.
  • Sem esse documento, a implantação não deve prosseguir.

Autorização de Cobrança

  • A autorização de cobrança é feita pela Joanna.
  • Este documento deve ser enviado ao cliente antes da liberação da base oficial.
  • O envio antecipado é crucial, pois:
    • No momento em que o cliente assinar a autorização, passa a valer o prazo definido no documento para o início da cobrança da mensalidade.
  • Sem a autorização assinada, não deve haver liberação da base oficial.

2. Primeiro Contato com o Cliente (KickOff)

  • Passo 2: Agendar a reunião de abertura de projeto com o cliente.
  • Durante essa reunião, será realizado o levantamento de requisitos.
  • Apresentação do cronograma de implantação: elaborado previamente. O cronograma pode ser alterado conforme a necessidade e o alinhamento com o cliente.
Elaboração do Cronograma:
  • Para base pequena: a implantação pode ser feita diretamente para a base oficial.
  • Para base grande: é necessário criar uma base de homologação antes de migrar para a base oficial.

3. Documento "Acordo de Escopo"

  • Passo 3: Após a reunião e a demonstração do cronograma, será elaborado o documento "Acordo de Escopo".
  • Conteúdo do Acordo de Escopo:
    • Datas principais para as etapas da implantação.
    • Definição do que faz parte e do que não faz parte da implantação.

4. Solicitação de Backup da Base

  • Passo 4: Solicitar ao cliente o backup da base, com data marcada na abertura do projeto.
  • Criar um link FTP para o cliente enviar o backup.
  • Após receber o backup, realizar o saneamento da base.

5. Saneamento da Base

  • Passo 5: O saneamento da base é um chamado separado do chamado de implantação, com o objetivo de corrigir erros existentes na base do cliente.
  • Tipo do chamado: “Tratamento de dados”.
  • As correções são feitas para garantir que a migração ocorra corretamente de acordo com as regras do cloud.
  • Enviar a APS para o cliente junto com o relatório de inconsistências gerado pelo desktop.
  • Erros nos arqjob de validações: Criar chamado de incidente/dúvida; o suporte irá encaminhar o chamado para a equipe responsável “Migração”. Quem corrige os arqjob de pré-validação é o desenvolvimento.
ATENÇÃO!

Para os vínculos empregatícios que já possuem categoria eSocial preenchido, não realizar alterações se os funcionários vinculados já foram ao eSocial.

Para vínculos empregatícios sem categoria eSocial, pode ser usado o seguinte comando como exemplo, lembrando que cada cliente possui uma listagem de veículos diferentes, então esse comando precisa ser ajustado em cada cliente com as categorias correspondentes.

update bethadba.vinculos 
set categoria_esocial = 

case i_motivos_resc 
when 6 then '306' 

when 18 then '701' 
when 20 then '306' 
else categoria_esocial end 
where categoria_esocial is null; commit;

8. Migração da Base

  • Passo 8: A versão do sistema deve estar atualizada. Colocar o print da versão do sistema no comentário do chamado.
  • Enviar para a migração no seguinte formato (comentário no chamado de implantação):
=== Solicitação de migração Oficial ===
Link drive do banco:
Relatório de validação:
Print da versão do sistema desktop:
Acesso liberado para usuário: user_conversao
Nome da entidade no sistema cloud: MUNICIPIO DE BELMONTE
Entidade que será migrada: 1 e 3.
Sistemas a serem migrados: Folha e RH.
Observações: Validação 199 foi aberto chamado pois os dados demonstrados no select não correspondem com a realidade.
  • Importante: Para que a migração saiba que a base está pronta para ser migrada, o status do chamado de implantação deve ser “Aguardando migração de homologação” ou “Aguardando migração de produção”.
  • Atualizar o status do chamado de implantação para garantir o controle do processo.
  • Durante a migração, treinamento com o cliente pode ser realizado.
  • Configuração do ambiente conforme a necessidade de cada vertical.
  • Após a migração, o status do chamado deve ser alterado para "Realizar acompanhamento" e deve ser alterado por quem migrou.

9. Treinamento com o Cliente

  • Passo 9: Realizar o treinamento com o cliente, que pode ser remoto ou presencial.
  • Após o treinamento, obter o documento assinado pelo cliente.
  • O documento deve listar todos os menus do sistema, para garantir que o cliente não alegue falta de treinamento em alguma área específica.

10. Realizar Acompanhamento

  • Passo 10: Durante o acompanhamento, efetuar as configurações de acordo com cada vertical e continuar o acompanhamento das etapas da implantação.

11. Finalização da Implantação

  • Passo 11: Após a conclusão da implantação, obter o aceite de implantação do cliente.
